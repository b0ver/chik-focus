# Чик! — реальная запись на фокус-группу

Отдельный инстанс с тёмной темой. Страница: https://b0ver.github.io/chik-focus/. Демо мастера и клиента остаётся в отдельном репозитории `chik-miniapp`.

## Согласованное расписание

20, 21 и 22 октября 2026 года, Москва (UTC+3). Встреча 30 минут, затем 15 минут перерыва. Начало: 15:00, 15:45, 16:30, 17:15 и 18:00 — 15 мест. Выбор Google Meet или Телемоста. Организатор — Евгений Попов, Telegram @ealpopov. Ссылку на созвон организатор отправляет вручную по контакту участника.

## Статус запуска

19 октября 2026: интерфейс опубликован на GitHub Pages, API развёрнут в Google Apps Script, приватная таблица и ежедневный триггер созданы. Анонимный доступ к API проверен. Через публичную страницу созданы и отменены тестовые брони; свободное время читается из сервера. Синхронизация с календарём организатора не включена.

## Как работает

- GitHub Pages публикует только интерфейс из `docs/`. Исходники — `dist/`; сборка — `node scripts/build.mjs`.
- Google Apps Script (`backend/Code.gs`) принимает запросы и хранит брони в закрытой таблице организатора. Идентификатор таблицы хранится в свойствах проекта, а не в GitHub.
- Сервер проверяет расписание, время, контакт, согласие, повторные запросы и занятость. ScriptLock охватывает проверку и запись, затем SpreadsheetApp.flush фиксирует изменения до снятия блокировки. Вторая бронь того же слота отклоняется.
- Повтор одного запроса возвращает ту же бронь. На один контакт разрешена одна активная запись. Отмена с личной ссылкой освобождает слот. Токен управления — 256 бит; сервер хранит SHA-256, браузер — токен. В публичных ответах о свободном времени нет участников.
- RPC использует POST-форму в скрытый iframe и postMessage: контакт не попадает в строку URL, нет зависимости от CORS-предзапросов. Ответ принимается только с Google origin и правильным случайным nonce. Origin не является авторизацией: доступ к конкретной записи требует токен.
- Автоматическое удаление записей — через 30 дней после встречи, ежедневным триггером. Таблица остаётся приватной, не публикуйте её и не включайте доступ по ссылке.

## Развёртывание

1. Создать Apps Script проект, поместить `Code.gs` и `appsscript.json` из `backend/`.
2. В аккаунте организатора выполнить `setup`: создаётся приватная таблица и ежедневный триггер удаления старых данных. Разрешения: Google Sheets и управление триггерами этого скрипта. Доступ к календарю, почте и Telegram не требуется.
3. Развернуть как веб-приложение: выполнение от владельца, доступ «Все» (анонимные посетители). Публичен только серверный API; код проекта и таблица не расшариваются.
4. Адрес `/exec` добавить в `dist/config.js` как `apiUrl`. Это публичная точка входа, не секрет.
5. Сборка, проверки, Git push. GitHub Pages: ветка `main`, папка `/docs`.

До подключения API интерфейс показывает закрытую запись и не выдаёт локальные данные за настоящую бронь. Продакшен-проверка обязательна: бронь, повтор запроса, блокировка слота, отмена и восстановление записи по личной ссылке. Тестовую бронь отменить.

## Управление

### Личный кабинет организатора в Telegram

Модуль `backend/OwnerBot.gs` добавлен 20 октября 2026. Он использует ту же приватную таблицу и работает отдельным минутным триггером. Публичное API бронирования и активные брони не меняются. Используются бесплатные квоты текущих сервисов.

- `/today` и «Сегодня» — активные встречи текущего московского дня.
- `/bookings` и «Ближайшие записи» — предстоящие встречи с контактами и выбранным форматом.
- Уведомления о новой записи и отмене; напоминания за 30 и 5 минут; одна утренняя сводка в дни фокус-группы в 08:30 МСК, с восстановлением пропущенного запуска до 12:00.
- `/status` — состояние отправки; `/help` — команды. Доступ только у заранее проверенного числового Telegram ID организатора в личном чате. Совпадение username не даёт доступа. Сообщения и нажатия других пользователей игнорируются.

Подключение: владелец отправляет боту `/start`; его числовой ID проверяется по ответу Telegram API. В Script Properties сохраняется `OWNER_BOT_CONFIG` с полями `token`, `ownerId`, `offset` (следующий update ID). Секрет не вставляется в исходники или публичную конфигурацию. В манифест добавляется разрешение `script.external_request`. После подтверждения Google-разрешения выполнить `installOwnerBot`: проверяются бот, личный чат и отсутствие конфликтующего webhook, создаются вкладка `OwnerNotifications`, персональные команды и один минутный триггер `ownerBotTick`. Первое сообщение содержит уже существующие записи; старые отмены не рассылаются.

Вкладка `OwnerNotifications` содержит только ключи, состояния, время и ID сообщений, без копий имён, контактов и токенов. Повторные запуски не дублируют успешные отправки. При явно подтверждённом Telegram 429 учитывается retry_after. При неизвестном исходе, прерывании или ошибке отправка не объявляется успешной и автоматически не дублируется: строки `pending`, `uncertain` и `failed` видны в `/status` и требуют ручной проверки. Блокировка бота, сбои Google и приблизительное время запуска триггера могут задержать или остановить уведомления. Успешный ответ API Telegram не подтверждает прочтение.

`pauseOwnerBot` останавливает уведомления без изменения броней. Участникам этот модуль ничего не отправляет; ссылку на созвон организатор передаёт вручную. Доступа к Google Календарю нет. Это кабинет одного организатора: без переноса и отмены от мастера, редактирования услуг и регистрации других мастеров.

Статус 20 октября 2026: Google-разрешение подтверждено, `owner-bot-v1` включён в 11:42 МСК. `installOwnerBot` завершился успешно; Telegram принял приветствие со списком действующих встреч и утреннюю сводку. Установлен один минутный `ownerBotTick`, первый запуск по времени прошёл без ошибок. Код выпуска — `4a9de7f0cb9dd47b7e1c10d8e290b222b9a62fc5`, [PR #2](https://github.com/b0ver/chik-focus/pull/2), [успешный CI и Pages](https://github.com/b0ver/chik-focus/actions/runs/39395269854). Публичный Apps Script `/exec` остаётся на версии 1; owner-модуль исполняется владельцем из текущих исходников проекта.

До активации сделана приватная копия таблицы и восстановление в отдельную приватную таблицу: совпали все заголовки и значения трёх исходных строк, включая ID, статусы и хэши токенов. Подтверждено отсутствие изменений исходных броней после установки. Адреса копий и журнал выпуска хранятся только в `.local/owner-bot-release.json`. Это ручная резервная копия и проверка копированием; автоматические бэкапы и полная отработка восстановления приложения пока не реализованы. Откат — `pauseOwnerBot`; публичный API и лист `Bookings` продолжают работать.


Брони смотреть в закрытой таблице из журнала запуска `setup` или Google Drive по названию «Чик! — встречи фокус-группы». Колонки Name, Contact, Role, Format, Status содержат данные для организации встречи. Форматы: `meet` / `telemost`; статусы: `confirmed` / `cancelled`.

Временно остановить новые записи — выполнить `closeBookings` в Apps Script. Чтобы снова открыть — `setup`. При изменении кода Apps Script нужно обновить его развёртывание; GitHub Push сам по себе сервер не обновляет. Не меняйте ID слотов, на которые есть активные брони. Для новых дат сначала обновите сервер, затем публичный `config.js`.

Участники не получают автоматические сообщения: в текущей версии подтверждение показывается на странице, ссылку на созвон отправляет организатор. Кнопка Google Календаря открывает создание события у участника, `.ics` скачивается вручную. Это не синхронизация с календарём организатора.

## Следующий этап: Google Календарь

Синхронизация пока не подключена. В таблице зарезервированы CalendarEventID и CalendarSyncState. При реализации: отдельный календарь фокус-группы, чтение busy перед бронью, создание/отмена события с устойчивым ID, идемпотентные повторы, очередь повторной синхронизации и отдельные права календаря. Google Meet создавать через Calendar conferenceData; для Телемоста потребуется отдельная ссылка. Пока блокируются только брони этого инстанса — внешние события Google Календаря не учитываются.

## Проверки и ограничения

`node --test tests/*.test.mjs` проверяет расписание, идемпотентность, занятость, блокировку параллельной мутации, отмену, защиту приватных данных, формулы в таблице и серверную валидацию. Ещё четыре проверки защищают форму подтверждения от позднего фонового ответа или ошибки обновления расписания. Это проверки на модели хранилища; живой Apps Script дополнительно проверяется через опубликованную страницу.

Нет платежей, рекламной аналитики и платных зависимостей. Применяются бесплатные квоты Google Apps Script и GitHub Pages; без регистрации платного тарифа. Защита от спама базовая (лимиты по контакту и скрытое поле); для широкой публичной кампании потребуется CAPTCHA/проверка контакта. Данные контакта предоставлены участником и не проверяются на владение.
